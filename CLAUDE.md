# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `bun test` — run all tests
- `bun test tests/scanner.test.ts` — run one test file
- `bun test -t "pattern"` — run tests matching a name
- `bun run typecheck` — `tsc --noEmit`, then `tsc --noEmit -p dashboard`
- `cd dashboard && bun run build` — rebuild the dashboard page; vite empties `dashboard/dist/` first and drops its `.crank-version` stamp, so `crank-mem dashboard` refuses as not built until `crank-mem setup` (or any `crank-mem upgrade`) restamps it
- `bun run format` / `bun run format:check` — oxfmt (pinned exact in `package.json`). `.oxfmtrc.json` leaves out `tests/fixtures/`, whose bytes the `.outline`/`.headers` goldens record, and all markdown, whose ADRs quote probe output verbatim and whose README shows JSONL one record per line

`bun test` needs `crank-mem setup` (or `bun src/cli/main.ts setup`) run once on the machine: `tests/digest-job.test.ts`, `tests/embedder.test.ts`, `tests/setup.test.ts`, `tests/cli-commands.test.ts` and `tests/dashboard.test.ts` read the real model it downloads into `~/.crank/models`.

There is no build step except the dashboard, which `crank-mem setup` builds into `dashboard/dist/` (`upgrade` rebuilds it when the stamp is not the clone's version). `bin/crank-mem` is a shell launcher that runs `src/cli/main.ts` directly under bun (or node >= 23.6, which also executes TypeScript natively). Hooks under `src/hooks/` import only `node:` modules, and `tests/hooks-imports.test.ts` enforces it; `src/daemon/` and `src/cli/code-symbols.ts` may carry packages, loaded by dynamic `import()` so every other command works without them. `package.json` pins three packages exact: `@huggingface/transformers` for the embedder, and `web-tree-sitter` and `@vscode/tree-sitter-wasm` for `outline` and `unfold`.

## What this is

Project memory for coding agents (Claude Code + Codex): a token-annotated file anatomy index plus a `cerebrum.md`, injected at session start and silently re-indexed on writes. With `crank-mem digest on`, finished Claude Code sessions, and live ones every 2 hours, are digested automatically into `.crank/memory.db` (SQLite with FTS5 plus local embeddings); after a digest, consolidation checks the digests' proposals and stale flags against the code and keeps `cerebrum.md`, which agents no longer write. Agents recall the store through `crank-mem search`, `timeline` and `get`, session-start sections and per-file history. Installed into a target project as `.crank/` (index, anatomy.md, cerebrum.md, memory.db, config.json, vendored hooks, backups, including the daily `backups/memory/` snapshots of memory.db); per-user state (digest spool, daemon heartbeat, stop state, models, the dashboard token in `dashboard.json` and the project registry in `projects.json`) lives under `~/.crank` (`$CRANK_HOME`). `skills/crank-mem-audit/` is the bundled audit skill; `tests/skill.test.ts` holds its `SKILL.md` frontmatter to the fields the skills installer reads.

## Architecture

Three entry surfaces share one core:

- **CLI** (`src/cli/`) — `main.ts` dispatches to per-command modules (`init`, `scan`, `digest`, `search`, `timeline`, `get`, `outline`, `unfold`, `restore-memory`, `setup`, `stats`, `dashboard`, `upgrade`, `uninstall`, plus the internal `daemon` and `job`) via dynamic imports. `main.ts` checks a command's flags against its entry in `src/cli/commands.ts` → `COMMANDS` before loading it: a flag without an entry fails as `unknown flag`, and a command without one prints usage and exits 1. `search`, `timeline` and `get` live in `src/cli/recall.ts`. `src/cli/settings.ts` merges hook entries into the agents' settings files and removes them, and holds `SUBAGENT_MATCHER`; `src/cli/backups.ts` copies every file `init` or `upgrade` is about to modify; `src/cli/codex-trust.ts` writes Codex `trusted_hash` entries (ADR 0002); `src/cli/codex-sessions.ts` tells `stats` whether the injection reached Codex threads (ADR 0006). `src/cli/code.ts` holds `outline` and `unfold`, and `src/cli/code-symbols.ts` holds the tree-sitter reader they share, with its per-language rule tables in `src/cli/code-families-compiled.ts` and `src/cli/code-families-scripting.ts`. `src/cli/install.ts` holds the ordered install items behind `applyInstall`, `repairInstall` and `removeInstall`, with the Claude and Codex wiring items in `src/cli/install-agents.ts`, the git-ignore items in `src/cli/install-gitignore.ts`, and their shared report and file helpers in `src/cli/install-support.ts`. `src/cli/dashboard.ts` is the foreground `dashboard` command (flags, the token file, the port-taken check, signals); `src/cli/dashboard-server.ts` → `serveDashboard` applies every guard and serves the static `dashboard/dist/` build and the `/api` routes over `node:http`, opening each store with `openMemory(file, "read")`; `src/cli/usage-metrics.ts` is the pure aggregator of usage lines behind `/api/projects/<id>/usage` and of the store's per-day upkeep behind `/api/projects/<id>/activity`; `src/cli/stats.ts` → `captureSummary` answers `/api/projects/<id>/health`; `src/cli/registry.ts` keeps the per-user project list that `init` and `upgrade` add to and `uninstall` removes from. The page itself is a separate Vite + React package in `dashboard/`. Runs from the clone.
- **Hooks** (`src/hooks/session-start.ts`, `src/hooks/post-write.ts`, `src/hooks/post-read.ts`, `src/hooks/stop.ts`, `src/hooks/session-end.ts`, `src/hooks/subagent-start.ts`) — invoked by the agents with a JSON payload on stdin. `init` vendors a recursive copy of `src/hooks/` (including `lib/`) into `<project>/.crank/hooks/` (`src/cli/vendor.ts`), so hooks run self-contained inside each target project while the CLI imports the same `lib/` from the clone. Consequence: everything under `src/hooks/` must work from either location and import nothing outside `src/hooks/`. `stop.ts` and `post-write.ts` emit nothing model-visible (ADRs 0004 and 0010). Claude subagents never see SessionStart, so `subagent-start.ts` emits `injection.ts` → `subagentInjection`'s text to the agent types in `SUBAGENT_MATCHER`: a 2 KB cerebrum excerpt, the code pointer and the recall pointer (ADR 0007). Stop and `session-end.ts` write the session's digest spool entry; `post-read.ts` adds a file's stored history when Claude reads it with Read or Bash (ADR 0009).
- **Daemon** (`src/daemon/`) — clone-only, never vendored: `daemon.ts` (one per user, sweep loop starting one `crank-mem job` at a time), `digest-job.ts` (one-shot digest of a spool entry into `memory.db`), `gateway.ts` (`claude -p` on the user's own login, the only spawn of `claude` — ADR 0008), `digest-prompt.ts`, `consolidate.ts` (consolidation after a digest: a `claude -p` run with read-only tools over the project reviews proposals, stale flags and bullets whose cited files changed, then edits `cerebrum.md` — ADR 0011), `cerebrum-edit.ts` (pure bullet numbering and edit application), `redact.ts` (always-on secret redaction), `transcript.ts` (transcript reader and distiller) and `embedder.ts` (local embeddings).

The shared core is `src/hooks/lib/`: `scanner.ts` (index refresh with time budget), `indexable.ts` (which relative paths the index may hold: binary, lockfile, test-path and name gates), `activity.ts` (git listing and churn-driven index activity), `store.ts` (anatomy-index.json load/save + anatomy.md render), `injection.ts` (both start injections: `sessionStartInjection` for SessionStart and `crank-mem stats`, `subagentInjection` for SubagentStart; each gathers its sources and returns the text and its usage event), `bullets.ts` (markdown bullet grouping shared by the cerebrum excerpt and consolidation — whole bullets, headings as hard boundaries), `cerebrum-files.ts` (memory file names, cerebrum's size limits, the `backups/cerebrum/` copies and audit-backup detection), `drift.ts` (one-line warning when the vendored hooks lag the clone), `symbols.ts` / `tokens.ts` / `describe.ts` (per-file analysis), `config.ts` (.crank/config.json + always-on sensitive-file filter), `lock.ts` (cross-process lock around index writes), `hook-io.ts` (stdin parsing, project-root discovery, `additionalContext` emission, `repoRelative` and `memoryPaths`), `memory.ts` (opens `memory.db` over `node:sqlite`, loaded through `process.getBuiltinModule`, and wires the `memory-read.ts`, `memory-search.ts` and `memory-write.ts` functions into its `Memory` object; also `restoreMemory` and `migrateStore`, the migration `upgrade` and `restore-memory` share), `memory-schema.ts` (memory.db's schema steps, `SCHEMA_VERSION` and `migrate`), `memory-read.ts` (the store's read queries), `memory-search.ts` (the store's hybrid `search`: FTS and vector results fused by reciprocal rank), `memory-write.ts` (the store's writes: digests, rejections, vectors, consolidation records and the daily `maintain`), `store-upkeep.ts` (memory.db's snapshot folder and names, the daily pass — snapshot every 24 h, keep 7 daily snapshots, delete rows stale over 90 days — the pre-migration snapshot and the save before a restore), `spool.ts` (per-user digest spool, daemon start, `digestGate`), `user-state.ts` (`<crank home>`, stop state), `shell-reads.ts` (files a Bash command reads), `apply-patch.ts` (Codex patch-text parsing), `debug.ts` (opt-in per-run JSONL trace to `.crank/debug.log`, off by default), `usage.ts` (`recordUsage`, the always-on usage line contract appended to `usage.jsonl` beside `memory.db` and rotated to `usage.1.jsonl` at 4 MiB), `wire.ts` (the server↔dashboard wire vocabulary: observation, proposal, stale, consolidation and usage shapes, their constants and guards; imports nothing, so the dashboard page imports it).

### Invariants

- **Hooks are advisory-only: every path exits 0.** Never let a hook throw, block, or emit errors that could break an agent session. A corrupt or missing index degrades to `emptyIndex()` and reconverges on the next scan.
- All index writes happen under `withLock`; hooks operate under hard time budgets (refresh budget, lock-wait budget) and report staleness in the injection rather than blocking.
- The sensitive-file filter in `config.ts` is not configurable — never index secrets.
- Model-visible output goes only through `hookSpecificOutput.additionalContext` on stdout; stderr is human/debug-only (see ADR 0001).
- Debug logging is subject to the same advisory-only contract: `debug.ts` never throws, never writes to stdout, and never records a sensitive path.

### ADRs record probe-verified agent behavior

`docs/adr/` documents live-probed facts about Claude Code and Codex (which hook channels reach the model, Codex's trust-hash formula, Codex tool shapes — notably: Codex has no Read tool, and writes arrive as `apply_patch` patch text). Design decisions rest on these probes; don't change behavior they cover without re-probing (method is in each ADR), and record new probe findings as ADRs.

## Testing conventions

Tests are black-box: hooks and CLI commands are executed as real child processes with agent-like stdin payloads via `runHook` and `runCli` in `tests/helpers.ts`, with `fakeClaude` standing in for the `claude` binary and `startDaemon` running the real daemon under a temp `CRANK_HOME` (no test runs the real `claude`), against temp projects built by `makeCrankProject`. Agent payload fixtures live in `tests/fixtures/payloads.ts`. Prefer this style over importing hook internals — assertions should hold against exit status, stdout JSON, and on-disk `.crank/` state.

`bun test` runs the test process in UTC with `TZ` unset, while `runCli` and `runHook` children run in the system zone, so an in-process local-date assertion passes against UTC getters too. Pin local dates through a CLI child with `TZ` in its env, in zones on both sides of UTC (`tests/helpers.ts` → `ZONES`).

The `spawnSync` timeout in `tests/helpers.ts` → `runCli` kills only the CLI child; a grandchild that hangs, such as `fakeClaude` with `auth: "hang"`, keeps running at ppid 1. After a RED run that hit the timeout, find leftover fake `claude` processes with `ps` and kill them.

To probe an fs failure path (such as `src/hooks/lib/spool.ts` → `settleEntry`'s non-`EEXIST` link fallback), run the probe under node: assigning `fs.linkSync` on the default `node:fs` import and calling `syncBuiltinESMExports()` reaches a module's `import * as fs` namespace under node 26 (the call threw the mock's `EPERM`) but not under bun 1.4 (it threw the real `ENOENT`).

### Load-sensitive tests

These fail under machine load, not from a code change. Run the full suite as `caffeinate -i bun test`; on battery a Mac sleeps mid-run and a different set of tests times out each time. `Expected: 0, Received: -1` on a test near 5 s is a timeout, not a crash: bun kills the children of a test that passes its 5,000 ms default, and `runCli` reports each as `-1`. A test's own timeout argument beats `--timeout`.

| Test | Symptom | Check before calling it a regression |
|---|---|---|
| `tests/daemon.test.ts` → `daemon retry holds`: `a hold belongs to one stem, a refusal holds like a failure, and exit 0 clears it` (gap < 800 ms), `a failing stem waits --retry-ms, doubling each failure up to --retry-cap-ms` (first gap < 700 ms), `a run past --run-timeout-ms is killed and retried, never parked` | Gap over the limit from load average about 1.5 | Ignore unless `src/daemon/` changed. Then run the file at the parent commit in a throwaway worktree (`git worktree add --detach <dir> <sha>`, `node_modules` symlinked in) under the same load. A solo rerun does not tell the two apart. |
| `tests/snapshots.test.ts` (5,000 ms default; `restore-memory` tests take about 4.75 s solo) | `Received: -1` | `bun test tests/snapshots.test.ts --timeout 20000` |
| `tests/digest-job.test.ts` → `a session started in a subdirectory stores its relative paths under that subdirectory`, `early exits settle the entry without calling claude` | `[5008ms]` | `bun test tests/digest-job.test.ts --timeout 20000` |
| `tests/digest-job.test.ts` → `an init line on an API key kills the run at once and stops digests with reason credential` (asserts < 2,000 ms) | Just over 2,000 ms | Solo rerun |
| `tests/code-cli.test.ts` (own `30_000` timeouts, which `--timeout` does not lift): `outline and unfold match the committed expectation for cpp.cpp`, `unfold matches by name, qualified name and line` | Timeout at 30 s | Solo rerun |
| `tests/debug.test.ts` post-write cases; `tests/session-start.test.ts` → `next steps come from the newest digest, only when short and not none` | 5,000 ms timeout in a full run | Solo rerun |

`docs/testing-load.md` holds the measurements behind this table (commits, load averages, gaps); record new ones there.
