# Load-sensitive test measurements

The evidence behind `CLAUDE.md` → "Load-sensitive tests": which tests failed under load, at which commits, and by how much. `CLAUDE.md` keeps the rule for reading such a failure; add new measurements here.

`tests/daemon.test.ts` → `a hold belongs to one stem, a refusal holds like a failure, and exit 0 clears it` asserts a retry gap under 800 ms, and spawn overhead under machine load pushes the gap past it. At load average about 2.5 it failed 5 of 6 solo runs (2 of 3 at `b7336dc`, 3 of 3 at `1a8eba3`), with gaps of 1,023 to 1,489 ms. A failure showing a gap just over 800 ms predates stage 2 and is not by itself a regression; a solo rerun does not tell the two apart.

At load average about 1.5 the hold test still failed every solo run made at `ea1698d` and after it, with gaps of 844 to 876 ms; it carries its own `25_000` timeout, so its failures are always the gap. When a test with no explicit timeout passes bun's 5,000 ms default, bun kills the children it spawned and `runCli` reports each as status `-1`, so `Expected: 0, Received: -1` on a test near 5 s is a timeout, not a crash. `bun test tests/snapshots.test.ts -t "the default source is the newest snapshot" --timeout 3000` reproduces it: that test passes no timeout of its own and runs about 4.0 s solo, and a test's own timeout argument beats `--timeout`.

The same file's `a failing stem waits --retry-ms, doubling each failure up to --retry-cap-ms` asserts a first gap under 700 ms and is load-sensitive in the same way: it failed at `cd03457` at load average about 5.5, and a full-suite run during the stage-5 final gate measured 778 ms. Neither daemon timing test is a regression signal unless `src/daemon/` changed. When it did, run the file at the parent commit in a throwaway worktree (`git worktree add --detach <dir> <sha>`, with `node_modules` symlinked in) under the same load: at load average about 2.2, `0641ff5` (Base) and `7b6384d` (which changed `src/daemon/digest-job.ts`) failed both tests alike, with gaps of 1,023 vs 1,048 ms and 1,717 vs 1,686 ms. A third test in the same `daemon retry holds` describe, `a run past --run-timeout-ms is killed and retried, never parked`, is load-sensitive too: at load average about 4 it failed at `3e16f63` (6,017 ms) and at `95caab4` (about 6,013 ms) while passing at their children, so read it the same way.

Other `tests/snapshots.test.ts` tests still run on bun's 5,000 ms default, and the `restore-memory` ones take about 4.75 s solo. At load average about 7, one or two of them reported `Received: -1` even when the file ran alone, at `f1a6e00` and at `50527b9` alike (2 of 15 failed, with the failing test changing from run to run), while `bun test tests/snapshots.test.ts --timeout 20000` passed 15 of 15 at `f1a6e00`. Rerun that file with `--timeout 20000` before reading such a failure as a regression.

`tests/digest-job.test.ts` → `a session started in a subdirectory stores its relative paths under that subdirectory` also runs on the 5,000 ms default and failed solo at `[5008ms]` at load average about 1.8, at `9770004` and at `fa6ba63` alike, while `bun test tests/digest-job.test.ts --timeout 20000` passed 50 of 50 at `fa6ba63`. `early exits settle the entry without calling claude` in the same file failed at `[5008.57ms]` in a full run at load average about 2.2 at `e3b0a97` and passed under `--timeout 20000`. Read its timeout the same way.

A full `bun test` on a Mac running on battery lets the machine drop into deep-idle sleep mid-run, and every test asleep past its timeout reports `Received: -1` or a timeout, in a different set each run: at `44b3725` two such runs failed 15 and 8 tests while `pmset -g log` showed deep-idle sleep throughout. Run the full suite as `caffeinate -i bun test`; on battery at load average about 5 that run printed `787 pass` / `2 fail`, the two `tests/daemon.test.ts` timing tests above.

`tests/code-cli.test.ts` carries its own `30_000` timeouts, so `--timeout` does not lift them. At load average about 5–7, `families` → `outline and unfold match the committed expectation for cpp.cpp` timed out at `c661c8a` (30,006 ms) and `03fd0e0` (30,004 ms) alike, and `unfold matches by name, qualified name and line` timed out in multi-file runs but passed solo. `tests/digest-job.test.ts` → `an init line on an API key kills the run at once and stops digests with reason credential` asserts the run ends in under 2,000 ms and measured 2,019 ms at `c661c8a` (load average about 2.6) and 2,142 ms at `03fd0e0` (load average about 9). In a full run at `03fd0e0` whose load climbed to 8.5, four `tests/debug.test.ts` post-write cases and `tests/session-start.test.ts` → `next steps come from the newest digest, only when short and not none` failed at bun's 5,000 ms default, and both files then passed 58 of 58 solo at load average about 9. Read any of these as load, not a regression, unless a solo rerun fails too.

`tests/cli-commands.test.ts` → `flags` → `--help and -h print the command's usage and change nothing` spawns `runCli` about 40 times under its own `20_000` timeout, so `--timeout` does not lift it. Each `--help` takes about 0.03 s run directly; the time goes to per-spawn cost. At load average about 3.6 it timed out at the 21st `expect` (`stats --help`, status `-1`) solo at `1598ef5` and at `690a2bd` alike, 20.01 s each, and timed out again at 20,003 ms in a `--timeout 20000` file run at load average about 4.4. In the same full run at `1598ef5` (load average about 3.7), `flags` → `an unknown flag exits 1 …`, `an unknown command prints the usage …` and `tests/recall-cli.test.ts` → `search flags` → `a malformed flag value or an empty query prints usage and exits 1` failed at bun's 5,000 ms default and passed in `--timeout 20000` file runs.

`tests/recall-cli.test.ts` → `search flags` → `a malformed flag value or an empty query prints usage and exits 1` failed again at bun's 5,000 ms default (5,002.88 ms) in a `caffeinate -i bun test` run at `920e31f`, load average about 4.5. That run printed `835 pass` / `23 fail`, every failure a timeout: 3 `restore-memory`, 17 `digest job` and the two `daemon retry holds` gap tests, with no `src/daemon/` change since `bfb963e`. `bun test <file> --timeout 20000` then passed `tests/snapshots.test.ts` 13 of 13, `tests/digest-job.test.ts` 50 of 50 and `tests/recall-cli.test.ts` 29 of 29 at the same load.
